# 证据专题：实验与开销

日常正文要求已并入[短指南](reader_workflow.md#正文)。仅在实验设计、指标、对照或开销资料难以判断时查这里的相关章节。

## 实验与效果

同一评测协议可容纳方法对比、消融和效率研究；先识别实验要检验的主张，再选择合适的解释方式，不把下表当必填类型。

| 证据 | 需要进一步核对的区别 |
|---|---|
| 标准benchmark | 数据、划分、任务和协议是否相同；训练目标与评估指标是否混淆；汇总口径是否一致 |
| 自设计对照 | 控制哪些条件，怎样选对照，观察是否直接对应所声称的改善 |
| 消融 | 改哪个因素、其余条件是否保持；同时改变多项时不能归为单因素效应 |
| 鲁棒性、规模、效率 | 条件或参数怎样变化，质量、速度和资源如何权衡；不能把单个规模的结果外推全部范围 |
| 定性或用户研究 | 样例/参与者选择、评价流程及判断依据；展示成功不能替代整体分布证据 |

指标是代理量时说明它与目标能力的联系和局限；没有可比baseline或数值也可以有有效证据。误差、重复次数和统计检验只按原文报告，不从平均值排序补造显著性。概览讲关键发现，详解在原实验章节解释证据到结论的过程。

## 开销与论文边界

先沿论文或作者项目页确认官方仓库，查README、运行文档与相关配置/脚本；按缺项查对应文件，不通读整个仓库。注明实际查阅的commit、tag或release和适用运行条件。

设备型号、batch size和迭代数属于配置，不等于最低硬件、实测耗时或费用；模型文件大小不等于运行显存。区分论文实测、仓库测量、运行建议和配置，不能把某次实验的版本/设备补套到条件未交代的另一项测量。

论文与仓库数据不一致时分别说明已知条件，不能挑一个数值冒充统一结论。无法访问、没有官方实现或未找到关键数据时写明实际来源范围，不据此声称零开销。只指出影响使用判断的缺口，不罗列无关缺项。

边界区分输入/数据/模型/环境前提、作者明确限制、实际失败和未测试范围；新增读者判断标明依据。理论界、算法复杂度和运行测量是不同证据，不能混为实际耗时或内存。
