# Pass 3 规范：定点打开黑盒（答疑）→ 边界剖析 → Gap 挖掘

## 0. 定位与进入条件

- Pass 2 给的是概述级"大致理解"（技术当黑盒）；**Pass 3 = 深度精读**：用户批注哪里，就定点打开哪个黑盒；用户要复现，才做复现级细节补全。实现细节（超参、内部机制）的答案只在这里出现；
- **必须由用户主动触发**（"进第三遍 / 看看我的批注 / 答疑"）。Pass 2 结束后严禁自动进入；
- **以批注文件为准**：第一动作是 Read `PaperVault/papers/<paper_id>/annotations.json`，严禁要求用户复制批注内容；
- **三段之间各停一次**：每段完成必须显式问用户是否继续下一段，禁止连发。

## 1. annotations.json 格式 v2（阅读器写回 / AI 写回）

```json
{
  "paper_id": "2026_xxx",
  "updated_at": "ISO 时间",
  "annotations": [
    {
      "id": "anno_1724659200000",
      "type": "text | block",
      "section_id": "sec-3",
      "block_id": "b-3-2-1",
      "quote": "被划选的原文（block 型为空）",
      "note": "用户的批注内容（可能被多次编辑）",
      "answer": "AI 的回答（AI 写入；缺失或空 = 未答）",
      "answered_at": "ISO 时间",
      "created_at": "ISO 时间",
      "updated_at": "ISO 时间"
    }
  ]
}
```

文件不存在或 `annotations` 为空 → 告知用户"未检测到批注"，问是直接进边界段还是先去阅读器批注。

## 2. 第一段：逐条批注答疑（定点打开黑盒）

**只处理 `answer` 为空的批注**（已有 answer 的是已答过的，跳过；除非用户指名要重答）。

对每条批注，按三层递进解答：

1. **白话类比**：生活化/跨域类比给直觉，一两句话；
2. **机理层**：数学/算法本质——结合本文上下文（引用论文的公式、图），说清"这里到底发生了什么"；
3. **工程层**：实现/使用时会遇到什么、常见做法是什么。

规则：

- **每答完一条，立即 Edit 写回该条的 `answer` 与 `answered_at`**（只改这一条，不动其他字段），再进行下一条——阅读器每 20 秒自动检测写回并在批注原位更新（含 toast 提示），用户无需刷新、不必等全部完成；
- 解答中可按需调用下文 §3 的类型深挖检查单，把该黑盒打开到用户问的深度为止，**不多给**（用户问效果就答到效果，问实现才展开实现）；
- 多条批注指向同一根源时可合并解答，开头列明覆盖哪几条 id，并逐条写回 answer；
- 解答忠实于论文；论文没讲的明确区分"论文事实"与"我的推断/领域常识"；
- **多轮循环**：用户读完回答后可能补充新批注再喊你——只答新批注（answer 为空的），节奏由用户掌握；
- 全部答完后告诉用户"批注已全部回答，阅读器会自动更新原位显示（如未弹出可刷新一次）"，再问是否进入边界段。

## 3. 类型深挖检查单（答疑弹药库，按需取用）

Pass 2 只讲黑盒效果；用户批注问到哪个黑盒，就按本文类型选对应项打开。**这些是问题清单，不是预设答案**——只展开被问到的，禁止把整张清单倒给用户。

### 类型 A：生成/学习模型类
1. 输入输出的数学表征与维度；坐标系/归一化空间；
2. 模型/网络结构：关键模块职责、连接方式、隐空间结构与压缩率；
3. 训练：损失函数逐项物理意义与权重；优化器、学习率、batch size、训练步数（论文给了哪些记哪些）；
4. 训练策略与课程：分几阶段、每阶段目标、渐进调度；
5. 推理全流程：输入到交付物每一步（含后处理/离散化/装配，重要算法给伪代码）；
6. 数据集：名称、规模、构成配比、预处理；
7. 评估指标：定义、本文数值、对比基线；
8. 消融：每个被剥离模块——去掉掉多少、**为什么**（机理归因）。

### 类型 B：渲染/采样/算法类
1. 问题形式化（目标函数/约束）；2. 核心推导关键步骤（公式+解读）；3. 算法流程与复杂度；4. 误差来源与控制；5. 实现细节（精度、加速、硬件取舍）；6. 收敛性/正确性论证思路；7. 对比实验每张关键图说明什么性质；8. 边界条件：什么输入下退化。

### 类型 C：系统/度量/实证类
1. 系统架构与模块职责；2. 数据/任务采集协议；3. 每个度量的定义与有效性；4. 主要发现的效应量与显著性；5. Threats to Validity；6. 可复现性（代码/数据/协议）；7. 与既有系统或结论的一致/矛盾。

### 类型 D：理论/分析类
1. 主定理陈述与直觉；2. 证明思路按关键步骤；3. 假设强弱与反例；4. 与已有结果的关系、tightness；5. 数值/构造性验证。

## 4. 第二段：边界与隐式假设剖析

先问："批注答疑结束。要继续【隐式假设与失效边界】剖析吗？"确认后输出三块：

1. **隐式假设清单**：作者在什么"理想条件"下才成立（数据分布、几何/物理、硬件与规模假设），每条注明依据来自论文哪部分；
2. **失效场景（Corner Cases）**：哪个假设被打破时、方法在哪一步崩塌、崩成什么样；
3. **复杂度与成本**：计算/显存/存储/数据量级，训练与推理两侧。

禁止臆造：每条论断要么有论文出处，要么标注"我的推断，依据是…"。

**写回阅读器（v4）**：输出后把三块分别填入 `paper-data.js` 顶层 `pass3.boundary` 的 `assumptions` / `failure_cases` / `cost`（字符串数组，Edit 只动这一处），重跑 `deploy_reader.py` ——用户刷新阅读器即可在文末"深度剖析"区看到。

## 5. 第三段：3 阶 Research Gap 挖掘

先问："要继续挖掘可拓展创新点吗？"确认后输出：

| 梯度 | 类型 | 要求 |
|---|---|---|
| 思路 1 | 渐进改进型 | 针对本文某个具体模块/损失/流程的可验证小改进 |
| 思路 2 | 跨域结合型 | 把本文核心机制迁移到相邻问题/场景 |
| 思路 3 | 痛点攻坚型 | 针对最致命局限的替代性新方案 |

每条含：**改进点 / 呼应本文哪个边界或局限 / 预期难度（低中高）/ 最小验证路径**。末尾主动问用户的具体研究方向以定制。

**写回阅读器（v4）**：输出后把每条 Gap 填入 `paper-data.js` 顶层 `pass3.gaps` 数组（对象字段：`type` 渐进改进/跨域结合/痛点攻坚、`idea`、`linked_limitation`、`difficulty` 低/中/高、`validation`），重跑 `deploy_reader.py`——"深度剖析"区同步显示。

## 6. 可选段：复现级细节补全（用户明说"我要复现"时才做）

按 §3 对应类型检查单**逐项**补全到 notes.md 或对话（用户选），此时代码仓库、超参表、训练日志、装配伪代码等实现细节全部落到纸面；论文未披露的项列出并给出合理推断与标注。

## 7. 沉淀与导出

三段（+可选复现段）全部完成后（用户随时可跳过某段）：

1. 按 `notes_template.md` 生成 `papers/<paper_id>/notes.md`：④ 节放批注答疑归档（每条：quote → note → answer 要点），⑤⑥ 节放边界与 Gap；
2. 引文按 `gbt7714_rules.md` 生成 GB/T 7714 与 BibTeX；
3. `vault_manager.py --vault <库> --status <paper_id> completed`；
4. 主动问一次导出：`notes.md` 原生 / docx（`md2docx.py`）/ PDF（阅读器打印按钮，或 `html_to_pdf.py`）——只导用户要的格式；
5. 汇报：文件路径 + 各节条数（批注几条全答、边界几条、Gap 几条）。
