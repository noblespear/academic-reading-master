# Pass 2 规范："大致理解" + 双语阅读器数据生成

## 0. 深度标准——Pass 2 的唯一验收（铁律）

> Pass 2 的目标是**大致理解**：读完能向别人讲清这篇论文**解决什么问题、输入输出是什么、分几步、每步用了什么技术、每步达到什么效果、创新点是什么**。至于每个技术内部怎么实现——这一遍不需要知道；那是 Pass 3 按用户批注定点打开的内容。

由此得出五条执行铁律：

1. **验收标准**：Pass 2 唯一的完成判据 = 用户读完流水线卡片 + 通过 self_check 复述自测，能向别人复述"解决什么问题 / 输入输出 / 分几步每步什么技术什么效果 / 创新点"。**不是**让用户理解每个技术内部怎么实现；
2. **技术黑盒**：每个技术只讲「名称 + 一句话它是什么 + 输入→效果」。专有名词知道"是什么、干什么用"即可，内部计算方式不展开。超参、损失逐项、训练细节一律**不写**（Pass 3 用户问到才打开）；
3. **通俗优先 + 术语首现必解释**：所有解释面向"第一次接触这个领域的人"。**任何学术用语第一次出现时必须给通俗解释**（是什么 / 像什么 / 干什么用；新手档重释义+比喻，熟练档一句轻解释；可内嵌 text_zh 括注或 concept 批注，二选一不重复）。每个概念先用大白话说清再给术语名；鼓励贴切的生活化类比（类比要自成一体，不引入新的行话）；短句优于长句，一句话不堆三个术语；数据用比较级表达（"快了三倍""从三成提到九成"）而非只丢原始数字；
4. **图示优先**：能画图讲清的结构不堆文字——方法主线由阅读器自动生成总览图；方法结构、模块关系、数据流向、方法对比应主动加 `diagram` 示意图（规范见 §2.5）；
5. **完整性与通用性**：sections 按原文结构逐段还原中文译文（阅读载体，规范见 translation_rules.md）；拆解框架适配任意论文，严禁把某篇论文的模块名当成通用标准。

## 0.5 挡位规范（整库设置，library.json 的 level 字段）

挡位在 skill 定位库后确认（无则问用户一次，`vault_manager.py --set-level` 写入），整库沿用；生成 paper-data.js 时把挡位记入顶层 `level` 字段（阅读器顶栏显示徽标）。

- **新手档 novice**——双层结构：**学术叙述保留 + 叠加通俗解释**（不是把学术味洗掉）：
  - **双层写法**：先写学术句（术语、严谨表述照常），随后用括注或自然的第二句补一层通俗解释——比喻、类比、数字人话转译（"绑骨串联 146 秒 vs AniGen 19 秒"要说成"别人两分多钟、它 19 秒，快 7 倍多"）。**不加任何固定标签**（如"说人话："），通俗层自然衔接即可；
  - **两条红线**：① 严禁只剩白话删掉学术表述（矫枉过正）；② 严禁只有学术没有通俗层——每个 goal/tech/关键句都要有成对的两层；
  - 步骤名、术语一律用论文原词（步骤名用论文章节名，可加口语副标）；术语首现的通俗层要讲"是什么 + 像什么 + 干什么用"；
  - **通俗层禁止"术语解释术语"**（不能用"拓扑合法性"解释"关节树"），比喻优先于定义；**一个概念一个比喻贯穿到底**；
  - **念给外行听**标准只作用于通俗层：想象念给不懂这个领域的同学听，他听不懂就重写；
  - 对照示例定调：❌纯学术"内积相似度经 Softmax 归一化为蒙皮权重"；❌纯白话"给每块皮和每根骨头打'合拍分'，越合拍的管得越多"；✅双层"计算蒙皮权重分配：顶点特征与关节特征的相似度经 Softmax 归一化（给每块皮和每根骨头打'合拍分'，越合拍的管得越多）"；
  - 批注解释更展开：重释义 + 比喻；concept 一句话化（先大白话后术语）；
- **熟练档 expert**——当前默认风格：术语首现一句轻解释（不强制比喻）；其余同通用铁律。**两挡批注密度相同**（每 block ≥1 条、核心块 2~3 条，见 annotation_guide.md §1）。

产出唯一：只生成 `paper-data.js`（结构见 paper_data_schema.md），HTML/JS/CSS 由 deploy_reader.py 部署。

## 1. 第一步：判定论文类型

先快速通读，把论文归入一类（可多标签，选主标签）。类型只用于：① 流水线节点怎么切（看框架图）；② 告诉用户同类阅读方向（若知道）。**深挖检查单已移至 Pass 3**，本遍不使用。

| 类型 | 判据 |
|---|---|
| **A 生成/学习模型类** | 提出、训练或微调一个模型，有训练流程与数据集 |
| **B 渲染/采样/算法类** | 提出一个计算过程：渲染算法、采样策略、数值求解 |
| **C 系统/度量/实证类** | 构建系统或 benchmark、做测量或用户研究 |
| **D 理论/分析类** | 定理、证明、复杂度界 |
| **S 综述类** | 梳理领域图谱 → 以"领域图谱模式"替代流水线（taxonomy 树 + 流派对比 + 开放问题），sections 照常 |

## 2. 第二步：方法流水线节点拆解（→ pipeline 字段）

把方法总流程提炼为 **3~8 个节点**的链（输入 → … → 输出）。每个节点按 schema 六要素填写：

- **goal** 这个节点解决什么问题（没有它会怎样），用通俗语言写；
- **input** 这一步拿到的输入是什么；
- **tech** 用了什么技术——**黑盒写法**：`技术名（一句话它是什么）：输入→效果`。例：`FlexiCubes（一种从连续场提取三角网格的技术）：场 → 可直接渲染的网格`。禁止展开内部机制；
- **why** 为什么用这个（**可选**：作者明确对比过替代方案才写，否则整个字段省略）；
- **gain** 效果如何——绑定论文图表证据（"Table 2: X→Y"），并用比较级转译成人话；没有量化就写定性出处；
- **benefit_next** 给后续节点提供了什么。

节点划分优先按论文自己的图 1 / 框架图来切。注意事项（原 pitfalls 场景）改用 `reading-reminder` 批注承载，且只写"新手读到这里最容易误解什么"。

## 2.5 示意图（diagram block）——多用图，少堆字

阅读器会**自动**为 pipeline 生成总览示意图条（节点名 + 技术短名 + 箭头，点击跳到对应卡片），这部分无需 AI 操作。AI 要做的是在正文里**主动画图**：

- **什么时候画**：方法总体结构（模块怎么连接）、数据如何流动与变形（A 进去 B 出来）、本文方法与旧方法的关键差异、双重表征/对应关系——凡是"关系与流向"类信息，一张图胜过三段话；
- **怎么画**：`{ "type": "diagram", "svg": "<svg ...>...</svg>", "caption": "一句话图注" }`，详见 paper_data_schema.md §5；
- **风格**：白底学术风——线条 `#4a4f57`、强调色 `#2b5cb8`、方框 `rx="8"`、中文文字 13~15px、箭头可手画小三角；`viewBox="0 0 860 H"` 等比自适应，高度内容不超过 ~360px；无脚本无交互无外链；
- **内容规则**：图里画"结构、流向、对应"，不画装饰；图内文字同样通俗（写"把模糊的场收敛成关节点"，不写"confidence-weighted Mean-Shift iteration"）；箭头旁可标"变成了什么"；
- **位置与 ID**：放在所属小节 blocks 数组**最前**（先见图后见细节），ID 用**追加型新编号**（如该节已有 b-3-2-1/2，新图用 b-3-2-3），严禁改动已有块的 ID（用户批注锚定在 ID 上）。

## 2.6 原文呈现：PDF 侧栏（不再转录 text_en）

- 完整原文由阅读器的"**原文 PDF 侧栏**"呈现：服务模式（open_reader.py 默认）下自动加载论文目录的 `source.pdf`，点击目录/章节标题联动跳页——**AI 不再全文转录原文**（生成成本接近减半，也避免转录误差）；
- 因此 `text_en` 为**可选字段**：仅关键句（定义、贡献声明等需要精确对照处）少量保留；
- **每个 section 标注 `page`（该节在 PDF 的起始页码）**——侧栏联动跳页的锚点，从 PDF 顺手标注，成本近乎为零，强烈建议全部标注。

## 3. 第三步：novelty 与 self_check（大致理解的验收工具）

- `novelty`：一句话创新点，直白说清"比之前的方法多做了什么、换来什么好处"；
- `self_check`：3~5 道复述题 + hint（hint 指向对应节点/字段，不直接给答案）。固定覆盖四问：① 解决什么问题、输入输出是什么？② 分几步、每步什么技术什么效果？③ 创新点是什么、替代了什么旧做法？④ 证据是哪张表、关键数字多少？

## 4. 第四步：正文与图表（效果层 + 通俗解读）

- sections 按原文逐段还原**中文译文**（translation_rules.md；text_en 可选，见 §2.6），AI 增值内容（批注/解读）全部停在效果层；
- `concept` 批注一句话化：**先大白话后术语**——"是什么（一句大白话）+ 干什么用 + （可选）深入检索词"；
- `formula` 的 `text_zh` 只写"这个式子在算什么、算完意味着什么"，鼓励生活化比喻（如"给每个候选打分，分高的赢"）；逐符号拆解是 Pass 3 的事；
- 实验图表：每张主表/主图 → 一个 block，`text_zh` 回答"证明什么主张、关键数字哪几个"，并转译成比较级人话——不做逐行归因；
- 提图用 `extract_pdf_assets.py <pdf> <论文目录>/assets`；只挑正文重点引用的图（5~15 张），对应关系不明宁可用文字描述；
- 框架总览图加 `figure` 批注：读图顺序指引（先看哪、箭头指什么）。

## 5. 第五步：落盘、部署与停点

1. 按 paper_data_schema.md §9 分段生成 `paper-data.js`；
2. `deploy_reader.py --vault <库> --paper <id>` 校验部署（JSON 报错按行号修复重跑）；
3. `open_reader.py --vault <库> <id>` 打开；vault_manager 状态流转 `reading`；
4. **🔴 停**，向用户交代阅读分层路径：
   > "建议先只读**顶部的总览图 + 流水线卡片 + 自测题**（5 分钟）：能复述'解决什么问题、分几步、每步什么技术什么效果、创新点是什么'就完成了大致理解——可以直接进第三遍、或先去读下一篇同类论文。答不上哪题，再下钻对应章节正文；想对照原文就点顶栏'原文'开 PDF 侧栏（点章节标题自动翻到对应页）。任何看不懂的词句/公式/图表，**划词、或悬停板块点铅笔图标写批注**——批注全自动保存到论文文件夹，无需任何操作；读完后回来说'进第三遍'。"

## 6. 输出前自检清单

- [ ] sections 覆盖论文全部章节，段落顺序与原文一致；每个 section 已标 `page`（PDF 起始页）；
- [ ] pipeline 3~8 节点，六要素齐（why 可省），每个 tech 都是黑盒写法、无超参无内部机制；
- [ ] novelty 一句话 + self_check 3~5 题覆盖四问；
- [ ] **挡位相符**：顶层 `level` 已按 library.json 记录；新手档逐条核对——术语首现都有通俗解释、每步有比喻、数字有人话转译；
- [ ] **通俗**：解释先大白话后术语；novelty/tech/gain/批注里没有未解释就使用的行话；
- [ ] **图示**：方法结构、数据流向、方法对比至少有一张 diagram（或说明为何不需要）；
- [ ] **text_en 未全文转录**（仅关键句保留）；所有 block id 唯一且符合 `b-<节号>-<序号>`；重生成时沿用旧 ID，diagram 用追加型新 ID；
- [ ] LaTeX 在 JSON 中反斜杠已双写；无尾逗号；deploy 校验通过；
- [ ] 批注密度合规（**每个 block ≥1 条、核心块 2~3 条，无空块**），类型分布多样，concept 一句话化，无空话批注；
- [ ] 未把其他论文的具体内容写进任何字段；未把 Pass 3 的深挖内容提前写进来。
