# 方法图与其他演示专题

日常原图插入、视觉覆盖和方法图要求统一见[短指南](reader_workflow.md#原图与必要可视化)。这里只在模块粒度难定、专门改图或用户要求额外演示时读取。

## 模块划分示例

以下是通用抽象示例，不是任何论文的原始结论：

| 过细拆分 | 总图中的功能模块 | 细节去处 |
|---|---|---|
| 计算相似度 → 跨层汇总 → 取索引 | 建立对应关系 | 正文局部解释相似度、聚合和选择 |
| 查候选 → 过滤无效项 → 合并可用项 | 筛选并整合候选 | 局部示意哪些对象被保留 |
| 分批统计 → 汇总数值 → 输出评分 | 评估结果 | 原结果图表和指标解释 |

如果合并掩盖了不同职责、关键分支或创新，就拆开。参考原方法图的功能分区并核对正文，不能把章节标题或算法每一行直接当节点。

## 现有方法组件

使用正文 `method_pipeline`、`placement:"body"` 和 `overview_framework` 登记。需要字段时搜索[组件合同](learning_support_guide.md)中的 `method_pipeline`，只读该类型。

布局辅助按非feedback前向依赖分层，同层保持并行，反馈单独处理；完整旧grid保留。边表示真实直接依赖，沿主路传递的普通参数放入说明，避免为每个参数再画捷径。用现有handoff字段提供 `[对应正文](#稳定块或章节ID)`，不增加自定义字段。

边标签保留于数据、悬浮提示与关系列表，避免图内浮动文字相互遮挡。点击更新解释和强调，布局保持稳定；说明自然展开，不做固定高度的内部滚动面板。窄屏由组件改为纵向排布，不能靠裁切或缩成小字去掉滑轨。

## 用户要求的其他演示

只有对象追踪、条件切换或参数变化确实需要操作时，配置当前已有类型。先给可读基准状态，只开放当前观察需要的变量和必要复位，让变化后的关系可见并就地解释。

假设演示标教学设定，不把公式变化推作真实准确率、延迟或费用预测。真实结果保留原单位和来源。仅翻页显示文字的steps默认不生成；现有组件不合适时保留准确的正文或静态图。新增共享能力另作代码任务。旧visual-plan仅在明确要求兑现旧计划时查，不作为新稿义务。
