# 周报素材中的HTML与批注

写周报时，将选定论文最终HTML和对应用户批注、追问、AI回答作为普通素材，与论文原文或实际工作记录一起参考。沿用原有写作与Markdown导出流程，不要求用户额外操作，也不生成强制材料包、清单、阅读确认或版本审核。

阅读实际页面的概览、详解、翻译、折叠讲解、公式、图表与图注，不仅看当前屏幕或首页摘要。HTML只是外壳、正文由paper-data.js加载时，同读其内容数据；用户问答取已保存的当前记录及相关历史，新版优先服务或SQLite，旧版使用annotations.json。长材料按需分段读取，不能把被截断的内容当作全文。缺失资料如实说明；图表中的关键判断仍查看原图或原PDF。读取方式由宿主使用现有工具决定，不规定额外转换步骤。

3.2直接读取可见正文、局部details及正文组件；不要求第二教学材料。旧3.1材料同时读取learning的普通词背景、完整公式讲解、类比和例子、共享blocks与组件静态fallback；不要因为页面关闭“说人话”就漏读。批注当前轮和history中的note_content/answer_content、attachments及study_state也作为上下文；数学、表格、代码、嵌套quote/details和图片说明完整保留。富文档文本回退可用rich_to_text，保留[教学示例]和原始LaTeX。

教学例子、参数演示、缓存计数和组件状态只是理解材料，不能充当论文发现、史料或访谈记录、实验数据或用户完成的研究成果。导出交互退化为完整图文/表格回退，保留AI与教学标记。引用论文数字、观点与材料解释仍核对原文，按实际证据组织周报，不增加强制素材流水线。

时间以用户指定的周次或日期范围为准；能从当前会话及“本周”“上周”等表达确定时直接采用并注明，只有存在歧义且影响时间归属时补问。区分提问、追问、回答各自时间，将UTC等时间换算到用户当地日期。本周新问题、对旧问题的新解答或修正可作为本周推进，过去的内容作背景；不能依据文件修改时间把历史互动全部计为本周工作。

从互动中提炼用户关心什么、认识怎样推进或修正、哪些问题还未解决。区分作者结论、AI解释与用户自己的判断，AI答复仍需必要的原文核验；不能据此声称用户已独立掌握、完成复现或实验。界面测试不当作研究工作，提交版不暴露阅读器或批注流程；个人讲解可针对实际疑问展开。
