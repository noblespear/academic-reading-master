# 周报详细讲解说明与汇报问答

说明为用户个人学习与汇报准备而写，独立交付 `.md`，与用于提交的周报配套。默认生成周报后附带说明；用户只要提交版时省略。给定已有周报时可直接补说明，不要求重写周报。说明不受1500–2500字限制，按理解需求展开，以清晰导航、必要背景和证据回溯控制长度，不扩展成无关教材。

## 内容组织

先提供可用于简短汇报的研究概述，讲清目的、当前认识及待解决问题；再解释周报各部分的含义、术语、图表和结论依据；最后给出老师可能追问的问题及可理解、可核验的回答。这是便于学习的组织建议，可按任务调整章节，不照搬某领域示例或强制每段使用相同模板。

逐节解释应回答该部分在论证中承担什么作用、关键方法如何工作、图表如何阅读、结论由什么事实支持、适用边界在哪里，以及如何关联后续工作。重点解释被周报压缩的推理连接，而非把原文换词复述。第一次出现专业术语给出简明释义；公式解释符号、单位、用途及假设，数学使用严格LaTeX并实际校验。假设例子与实际数据明确区分。

周报来自阅读器时，也参考[HTML与批注素材](report_reading_inputs.md)。结合用户实际追问和理解变化决定哪些机制需深入说明，保留尚未解决的疑点；不能只根据提交版另编一份通用教程，也不能将 AI 回答视为用户已掌握或已验证。原始阅读器不可得时，仍可基于已有周报及可核验原文补说明。

## 总括问题的覆盖

以下六类按报告内容覆盖，可以在正文或问答中讲清，不要求两处重复，也不是固定标题或顺序。调研、理论、解释性、实证、开发与探索类都按实际对象解释；不适用项直接省略，需要但未确定的信息再说明。

| 内容 | 必须讲清的要点 |
|---|---|
| 研究或工作目标 | 面向什么对象、回答什么问题、研究范围与约束，以及领域目标、本项目目标和本阶段目标的区别；输入与输出仅在适用时说明 |
| 共性困难 | 哪些困难在所分析路线间共同存在，哪些只属于特定路线；解释产生原因与取舍，不笼统声称“所有研究都如此” |
| 整体方向 | 相关工作如何尝试解决问题、路线之间的联系与差异、当前工作位于哪里；限定归纳范围，避免将有限阅读冒充全领域共识 |
| 方法或研究路径 | 核心概念、机制、材料处理或推导环节、假设及替代解释；区分作者的方法、用户已做工作与建议探索的方案 |
| 判断依据 | 理论分析说明前提、推导与一致性；解释性研究说明材料来源、语境及解释依据；使用指标时说明含义、单位、方向及统计口径，不编造分数或目标值 |
| 论证或效果评定 | 结论如何由材料、推导或数据支持，反例、替代解释与不确定性如何处理；适用时说明基线、条件、数据划分、消融归因以及成本 |

覆盖要求随任务解释，不要求所有报告都有性能实验。调研类重点说明比较或综合的依据、认识如何形成及候选问题；理论类说明前提、定义、推导及结论范围；解释性研究说明材料选择、语境、解释连接及其他可能读法；实证类按设计说明变量、样本、观察或统计口径与结果归因；开发类说明需求、实现机制、功能验收及适用的性能与维护代价；探索或排障类说明假设如何被证据支持或排除。研究目标、项目约束与当前阶段完成标准分别说明。

## 汇报问答

每个问题先给可口头表达的简短回答，再展开机制、证据与必要边界。选择与本报告最相关的追问，不凑数量。除六类总括问题外，可按需要说明：为什么研究它、已有研究留下什么问题、创新性目前能确认到哪一步、概念如何界定、为何选择这些材料、如何处理反例或替代解释、结论来自原文还是自己的分析。实验或开发报告可进一步讨论基线、变量、指标取舍、方案调整及相关资源与时间。

短答必须与长解释、提交版和实际证据一致；不能为了答得肯定而掩盖未决项。重要判断指出论文页码、图表、史料、访谈或调查记录、推导位置等实际依据，实验与开发工作可指向实验记录或源码版本。工作尚未开展时给出适用的后续研究方案；硬件、预算或验收阈值只在影响本项工作时说明。不能将降低某个代理成本直接等同于完整系统收益，也不把“尚未在本材料中见到”说成“领域无人研究”。

## 生成与导出

输入JSON含title、report_path、可选report_sha256与introduction、sections、可选section_links、faq和sources。sections使用与周报一致的title/paragraphs/items/tables/images。section_links条目为report_heading（原报告中去掉Markdown井号后的完整标题，含编号）及explanation_heading（说明sections中的完整title），便于核查解释与原章节的关联。无需强制覆盖所有原文标题，已有映射必须真实且唯一。

faq每项含topics、question、short_answer、explanation（段落数组），可选evidence（证据文字数组）与limitations。topics沿用goal、challenges、directions、methods、metrics、evaluation，其他问题可标other；metrics用于适用的指标问题，evaluation可涵盖论证或效果评定，不为非量化研究编造指标。这些标签仅描述问答，正文已解释的内容无需为补齐标签再编一问。sources放适合用户查证的论文或资料，不泄露认证、服务信息或无关内部流程。

运行 `python scripts/export_report_explanation.py --input <讲解JSON> --output <周报详细讲解说明.md>`。导出器只读源报告，拒绝覆盖源报告及路径别名；如提供report_sha256则检查版本一致，验证已有章节映射、表格、图片与严格LaTeX。说明注明个人用途并链接对应周报；源摘要只写入导出结果，不展示在成品。生成后核对两份文件一致性、整份说明的内容覆盖、FAQ与评测口径，并检查图表可读性。源报告更新后重新核查对应讲解，不能假定旧说明继续适用。
