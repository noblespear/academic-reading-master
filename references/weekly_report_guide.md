# 调研类与工作类 Markdown 周报

最终只交付 `.md`。默认正文、图注及表中文字合计约1500–2500字。以连贯文字解释问题、比较和结论，每份周报必须配有简洁易懂、服务论证的图或表。根据材料选择流程图、机制图、比较表、能力矩阵或结果图；不固定图表类型、数量或章节，不复制示例的领域内容、研究结论及工作经历。Markdown表格压缩共同设置、可比较机制或结果，不将长段落塞进单元格代替写作，不凑图表、字数或虚构工作。

默认同时提供两个独立Markdown文件：用于提交的周报，以及用于个人理解和汇报准备的[详细讲解说明](report_explanation_guide.md)。用户明确只要提交版时省略配套说明；用户给定已有周报时可只补说明。提交版仍遵循本篇幅与写作规范，教程、展开推导和老师追问放入说明，不混入提交版正文。先确定提交版，再依据其实际内容生成说明，两份文件不能相互覆盖。

正文面向导师或研究同事，直接汇报研究问题、具体工作、方法差异、关键证据与阶段结论。不要呈现 skill、阅读器、入库、批注记录、导出测试、来源收集等工具流程，也不要用“本次纳入7篇已入库论文”之类的库存说明代替研究进展。论文名称用于自然交代研究对象，表格集中比较真正影响判断的差异；不写给新手的阅读教程或周报写作说明。用简洁小节和必要的重点句增强层次，按研究问题组织材料。

参考文献或证据来源可按任务需要与用户偏好保留，作为简短附录；正文仅在有助于追溯关键判断时引用，不让文献列表替代研究分析。出处与核验过程在生成材料中留存，成品不出现工具内部记录链接或处理流程；关键数据应自然说明归属及适用条件。确有影响结论的局限应简洁写明，不反复插入“尚未复现”“不能证明”等说明性段落。

示例用于提炼论证完整性的检查要点，而非所有类型通用的章节顺序。报告应交代工作目的、实际内容或观察、支持判断的依据及其解释，并将后续安排与阶段认识衔接。证据可与方法、结果或讨论一起呈现；比较只是分析工具之一，有自然对照时采用，没有对照时可分析趋势、可行性、异常或完成情况，不为满足顺序强造比较对象。探索性工作和失败结果可保留未决问题，不强行形成确定结论。结构由本阶段最需要回答的问题决定，逻辑推进不能退化为论文、日期或操作清单。

图表要回答具体问题并嵌入适合本任务的论证。流程图显示关系、作用位置或因果链；比较表突出影响判断的差异；矩阵暴露能力组合或待验证项；结果图说明趋势、对照或异常；进度表可压缩完成状态与验收信息。正文解释图表反映的发现及适用条件，并与阶段认识或后续工作关联。综合归纳的框架需说明是分析视角，矩阵中的“不具备”必须有依据，未核验项目标为未核验；不将文献覆盖不足直接宣称为领域空白。

按内容选择结构，以下仅为常用组织方式，可合并、调整或省略不适用部分，不新增导出类型：

| 报告内容 | 常用组织方式 | 主要分析任务 |
|---|---|---|
| 调研类 | 调研背景与目标、相关方法、比较分析或主题综合、阶段认识、后续工作 | 说明研究现状、方法联系及待研究问题 |
| 工作类：实验或复现 | 研究目标、实验设计、实验结果、结果讨论、后续实验 | 用设置和结果支持解读，解释偏差与局限 |
| 工作类：开发或实现 | 工作目标、方案与实施、完成情况及验证、问题分析、后续工作 | 说明实现内容、验收结果与技术取舍 |
| 工作类：探索或故障排查 | 现象与目标、假设或尝试、验证结果、原因分析或未决问题、后续验证 | 说明判断如何随证据变化，保留不确定性 |

只汇报阶段进展时可围绕目标、完成结果、影响与问题、后续安排组织，不必强设方案比较。素材多时详细记录留在原材料，不把周报扩成长篇教程。

标题采用简洁、客观、范围明确的学术表述，以研究对象或任务加工作内容为主，必要时注明初步、阶段性等限定，不夸大为全面综述、系统验证或创新结论。主标题可表述为“某类方法的调研与比较分析”“某方法在某任务上的性能评估”“某模块的设计与实现进展”；副标题仅用于明确范围，非必需。章节标题概括实际学术内容，如“实验设计”“结果与讨论”“方法局限与研究方向”，同级标题保持一致的层次与措辞；尽量减少口语提问、宣传性修辞和“从证据到阶段判断”等描述写作过程的标题。图题、表题也采用内容明确的名词性短语，保持编号与术语一致，不在标题中预设尚未验证的因果或优势。

调研使用选定论文、已核验阅读资料和原文依据。工作使用当前会话、用户指定日志、数据、代码；collect_report_sources.py可对明确路径筛选素材，mtime只作筛选，不能据此说完成实验。已有上下文足以确定范围、日期或事实时直接使用；只有缺失信息影响报告准确性时集中补问，可选姓名等信息缺失可省略。示例只控制结构、研究叙事和密度，不能提供未发生的工作。无本地实验结果时汇报方法比较与调研认识，不冒用论文指标作为自己的实验结果。

写作时直接把选定论文最终HTML和对应批注问答纳入素材，覆盖概览、详解、翻译、折叠讲解和图表；页面内容由脚本加载或批注保存在后台时，同读实际内容数据与已保存记录。依据互动提炼关注点、理解修正及未决问题，结论仍与原文核对。按提问、追问和回答的实际时间区分本周进展与历史背景；旧问题在本周得到推进可汇报该推进，不能把全部历史阅读算作本周完成。具体见[HTML与批注素材](report_reading_inputs.md)。由宿主读取即可，不增加强制中间材料、清单、逐块确认或导出限制。

每项关键判断保留必要证据和适用边界。不改数值、条件和局限，不跨不同指标直接排名。既定下一步与建议区分，不替用户承诺执行。

生成JSON：type为research/work；title、可选name/period_start/period_end/subtitle、introduction、sections。每节title、paragraphs、可选items、tables、images。table含caption和rows（首行为表头）；image含path和caption。自包含流程图可在paragraphs中保存完整mermaid代码块，另用正文或图注解释。sources仅放适合展示的正式书目或证据文字；通过布尔值include_sources控制是否展示，按任务需要选择，无需另设确认停点。工具内部核验记录放在internal_evidence中，不进入成品。宿主负责内容、来源及篇幅，正文仍需自行去除工具流程用语，不通过机械替换处理正常研究术语。

运行 `python scripts/export_weekly_report.py --input <JSON> --output <报告.md>`。脚本仅接受.md，生成UTF-8 Markdown、合理标题层级、空行和标准表格，并提示篇幅。1500–2500字为默认目标，按实际工作量调整，不为达标凑字或压掉关键内容；只有用户明确要求硬性字数范围时附加 `--strict-length`。所有数学使用严格LaTeX；输入可用 `\(...\)` / `\[...\]`，导出标准Markdown的 `$...$` / `$$...$$`，由阅读器同版本的本地KaTeX实际校验。无公式时只需Python标准库；有公式需要宿主Node.js，可通过ARM_NODE_PATH指定运行时。无效公式明确报错，不伪称通过。

交付前检查最终md的逻辑推进、图表是否支持关键判断、表格列数、图片链接、来源、篇幅以及公式校验结果；流程图需核对渲染与可读性。导出器会拒绝没有任何图表的报告，图表的实际价值由内容检查保证。图片引用需可访问，单文件交付优先使用Markdown表格与自包含Mermaid图。不得调用Word/PDF导出作为周报出口，也不套用另一个“500–1000字、无表格”的周报模板。
