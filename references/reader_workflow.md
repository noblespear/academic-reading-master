# 日常创作短指南

新建、续写和局部修订共用这一份指南。默认成品是讲清楚的正文、简洁研究框架图、相关原图表和必要局部图；其他手册遇到对应问题再查。按“核验与主线 → 连续正文 → 插图与必要视觉 → 装配预览 → 集中审阅”推进，局部任务从相关位置进入。

## 准备

确认论文版本、PDF页数/哈希、阅读顺序和当前范围，识别其研究类型及主要依据；关键引文、原式与原图看实际页面核验，不只信提取文本或图注，无法辨认处留待核对。只维护一份简短底稿 `intermediate/reading-plan.md`，记来源、讲述主线、关键疑点和实际修订。框架图骨架直接保存为最终组件数据，不另抄计划或逐段媒介表。

## 正文

概览保留以下五个顶层章节及顺序，围绕“研究问题 → 研究路径与贡献 → 论证及发现 → 适用范围”连续讲述；每节承接上一节留下的问题，具体分析与完整依据在详解中展开。章节职责随论文类型落实，实验、量化指标和开销分析仅在相关时展开。

| 章节 | 读者应获得的认识 |
|---|---|
| 问题背景 | 从研究情境或学术争论说明本文关心什么、已有认识有哪些不足，由此引出研究问题 |
| 研究框架 | 承接问题说明研究思路、对象或材料、关键概念及分析路径，讲清各部分如何相互支持；前部放完整可点击框架图 |
| 主要贡献 | 说明相较已有研究新增了什么认识、材料、解释、命题或方法，以及这些贡献如何回应研究问题；按原文界定贡献程度 |
| 论证与发现 | 解释主要结论由哪些推理或证据支持，展示关键发现、分歧与其他可能解释；依据可来自实验、观察、访谈、文本、史料、证明或文献综合 |
| 适用范围与局限 | 说明结论依赖的前提、材料覆盖、情境与解释边界，以及仍待解决的问题；研究涉及实施或资源约束时，再说明相应条件与代价 |

详解保留原论文的大章节及其顺序，在对应位置补背景和推理，不重排为自拟教学目录。像老师带着读者理解一样把话说全：讨论什么对象，为什么采用这个概念、材料或步骤，它如何支持接下来的判断。用完整句子和自然的“因为、所以、因此、但是、当……时”等连接词明确因果、条件、转折与承接，少用省略对象或逻辑的碎短句。区分定义、推导、研究设计、材料记载、作者解释和经验观察；不把先后当因果，也不编造作者选择的唯一最优理由。

术语按领域习惯使用，保留通行英文写法；仅在有助于理解或回查原文时补充中英对照，后文保持称呼一致。

执行内置[反防御性表述](../vendor/anti-defensive-writing/SKILL.md)的基本原则：先讲结论、机制与依据；影响理解的前提和限制就近说清一次。将重复的“不能据此证明……”“这不代表……”改为有信息的正面适用范围，保留确有教学作用的概念辨析，删去无信息的免责与自我否定。专门润色时再加载完整规范。

论文涉及数学时，先说明要描述的量与关系，再给完整原式，就地解释符号、维度/单位、运算、成立条件和用途。推导补足中间理由，区分等价、近似和新增假设，不能只列变量表。概念论证则说明定义、前提、推理步骤与可能的反例；材料分析说明选材及从材料到解释的过程。必要时用具体对象、比喻或可复算的试算接上理解；自拟数字与例子标为教学设定。正文独立可读，长支线可就地折叠，不生成第二套“AI说人话”或隐藏讲解副本。

论证按实际依据讲。实验和定量研究解释研究设计、对照、指标与统计口径；观察、访谈与案例研究解释材料选择、分析过程及解释范围；文本与史料研究说明来源、语境和解释依据；理论研究展开前提、推理与反例；综述说明检索或选材范围、组织方式、共识与分歧。按本文实际采用的路径选择，不给每篇补齐所有类型。不凭均值声称显著，不以个别案例代替总体证据，也不把解释立场写成已经确证的因果事实。

适用范围优先依据论文实际陈述及相关材料判断，区分研究前提、材料或样本覆盖、作者明确的限制与读者推断。仅当资源需求影响研究理解或用户明确关心实施可行性时，再核查时间、算力、设备、材料获取或人工代价；有官方实现时按需查相关文档，保留版本与条件。不把配置当实测，不推算未报告的费用，也不为无关论文强行查代码仓库。

## 原图与必要可视化

写正文时就按图片已在预定位置的状态自然讲清内容，先完成连续论述，再将支持论点的原图表插入合适的段落边界。必要的观察、解释和隐式推理留在正文，不逐图另加读图口播。图名简短；额外的面板、颜色或局部细节提示用现有quote块紧贴图下，由组件统一使用引用式字体，不重复正文，没有补充就不加。裁切保留图号、轴、图例、单位和比较条件，不留半行图注或邻图残片；复用已核验资源，不能用自绘图替代应看的原图。

正文稳定后反查研究框架、核心贡献、关键概念或对象的对应及主要发现，可适当丰富有帮助的关系图、局部示意或对照，使重要关系与变化更容易看见。一图可解释多个问题，同一原图可在独立阅读的视图中复用；不设图数配额、不为凑图拆碎正文、不逐项写不配图理由。

研究框架图按真实关系组织：方法论文可用功能环节，理论论文可用前提、命题与推理，实证或解释性研究可用问题、材料、分析视角与发现，综述可用分类与比较关系。通常先试4–7个主要节点，保留重要分支、并行与相互支持的关系。默认只显示短标签和必要连线；点击后说明节点含义、依据、与其他部分的联系及正文入口。沿用 `method_pipeline` 和布局辅助脚本；其 `inputs/outputs` 可表示论据与形成的认识，`flow/cause` 解释实际关联及理由，不把逻辑关联画成未经支持的因果或算法流程。细节放正文局部展开。

按本项目[可视化规范](visual_authoring_guide.md)组织演示：明确要看清的对象、关系或变化，保留可读基准状态，让必要操作产生可观察结果。其他交互只响应明确需求。公式／参数探索器仅用于确需调参观察重要变化的关键公式；简单、次要或一次试算就能讲清的关系用正文、例子或静态图。仅逐页显示文字的 `steps` 默认不生成。阅读器使用现有组件与本地资源，专门图形设计再查[制图适配](visual_authoring_guide.md)，不加载会话HTML宿主规则。

## 装配

从最接近论文研究路径的脚手架填正文，沿用稳定ID和固定阅读器。method用于方法研究，theory用于形式理论，survey用于文献综述，system用于系统研究，empirical用于定量或质性实证研究，argument用于概念论证及文本、史料解释；混合研究按主线选择并调整任务提示：

    python scripts/init_reading_content.py --paper-id <id> --preset <研究类型> --output <论文目录>/paper-data.js
    python scripts/prepare_method_pipeline.py --input <骨架.json> --output <组件.json>
    python scripts/deploy_reader.py --vault <库> --paper <id> --preview --preview-dir <隔离目录>

新稿保持 `schema_version:3`、`content_contract_version:"3.2"`；`overview.sections`和`explanation.sections`承载正文，全文翻译初始为 `translation:{status:"deferred"}`、顶层 `sections:[]`。数据是纯JSON赋值，不含脚本；保留证据性质及关键引文、图表、公式与研究依据必要的内部定位，不要求普通段落来源索引。概览与详解不展示逐段或章节来源入口，保留顶部原文PDF入口。

公式使用LaTeX，HTML行内为 `\(...\)`、独立formula块为裸latex，JSON反斜杠双写；核对实际渲染。草稿按返回的隔离HTML查看，不启动正式答疑或写用户状态。字段含义不清或校验报错时只查相关合同，不预读全部schema、示例与组件目录。

## 分工与复验

只委派独立且值得并行的范围，交接相应原文、主线、必要术语/ID和输出位置，不给每人整篇历史或整套手册。独立审阅者不参与受审稿编写、装配或修正；无法独立审阅时如实记未验证。

首次交付做一次完整内容验收：从原文反查五节主线、关键隐式推理、原式/数值、原图位置及讲解、必要视觉覆盖；查看桌面/窄屏并操作本篇研究框架图和一次实际答疑。字段齐全、mock或脚本通过不能替代内容和真实运行。问题集中交作者修正，此后只复验问题位置、受影响及同源内容；没有新证据不重复整篇输入、全文审查或全套组件回归。底稿只记实际问题、修正与结论，不增加评分表或审批流程。

如实填写审阅者、事实核验与 `content_status:"ready"` 后正式部署：

    python scripts/deploy_reader.py --vault <库> --paper <id>
    python scripts/open_reader.py --vault <库> <id>

交付页面、启动方式和实际完成范围；实质事实错误、必要视觉缺口、答案解析失败和历史回归须先解决。旧稿不批量重写，不补造翻译或改动认可正文与锚点。

| 用户触发全文翻译 | [翻译规则](translation_rules.md)；出现覆盖/断栏异常再查[翻译复核](translation_review_guide.md) |
