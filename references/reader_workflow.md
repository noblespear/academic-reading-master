# 日常创作短指南

把论文直接转成完整图文阅读器。复用 skill 加载时已检查并确认的[分环节模型选择](model_and_context_policy.md)，由宿主实际调度对应模型读取必要原文、直接生成正文或图资产，装配并交付。普通阅读只需确认 `writing drawing`；未用的答疑和翻译角色不阻塞创作，明确选择继承的字段由宿主决定。不另设规划、审阅、评分、验收报告或答疑测试任务。

## 成品内容

以下内容直接组织进现有概览和详解，不拆成额外页面或中间文档。

| 内容 | 成品要求 |
|---|---|
| 概览 | 保留问题背景、方法框架、创新点、实验与效果、开销与论文边界五节，连贯讲清问题、做法、贡献、证据与使用条件 |
| 详解 | 沿原论文大章节及顺序展开，保留关键内容，补足背景、术语、机制和中间推理；小节内容融入章内自然段，不另造教学目录 |
| 方法总图 | 每篇完整阅读器必须有一张中文静态架构图，放在概览的“方法框架”前部。一次呈现输入、主要模块、输出及真实分支、汇合或反馈；理论论文画论证关系，综述画分类与比较关系 |
| 原图与可视化图片 | 呈现支持核心机制、空间/矩阵关系和主要结果的原图；原图不足以解释关键关系时补必要局部示意。正文谈到某图的颜色、位置、形状或变化时，必须在附近放出对应图 |
| 表格与数据 | 关键结果、消融、参数或开销对比保留可读表格，采用原表裁图或结构化表格；保留指标、数值、单位、条件和必要脚注 |
| 公式与推导 | 关键原式用 LaTeX 展示，就近说明符号、用途、条件与必要中间步骤，让读者能从前式跟到后式 |
| 算法步骤与例子 | 理解机制需要时保留算法、伪代码或操作步骤；用小例子、试算或局部示意补足难点，标明教学设定，直接嵌入相应章节 |
| 论文信息与原文入口 | 保留题名、作者、年份等已知信息及原 PDF 入口，图、式和关键实验有必要的内部来源定位 |

概览、详解和方法总图为固定组成。原文中影响理解的内容完整呈现；AI 同时自主判断哪些背景、推导、例子、表格或可视化能帮助读者，并直接补到相应位置，无须等待用户逐项指定。不设图表数量配额，也不逐项写“不适用”说明。

补充可包括：把原文散落的信息整理成对照表，展开省略的推导或等价公式，用教学数字试算，绘制机制示意，以及配置有助观察变化的现成演示。以能否消除具体理解障碍为取舍依据，不另写判断过程、补充清单或视觉计划。基于原文整理的内容保留出处；补充推导就近说明前提，教学例子/模拟标明设定，实验设想标为建议。未报告或未实测的数据不写成论文实验结果。

## 阅读与写作

读取用户提供或文献库已有的论文正文，复用提取文本和图片。图表、公式无法从文本确定时查看对应 PDF 页面。缺少原文时说明实际覆盖范围，不据摘要补写全文。只有具体疑点或用户要求才补查外部材料，不默认搜索官方代码仓库。

正文用连续自然段讲清操作作用于什么、为何需要、怎样改变对象及结果如何支持下一步。方法正文独立走通完整过程，图作为配合。关键推导写出连接结论的步骤；区分定义、推导、设计和实验证据。正文、表格和必要补充一次组织进最终数据；表格直接保留原值、单位、指标方向、条件和脚注，不先写散文版再转表。长文可分章直写，完整后仅因具体缺漏、错数或渲染错误修改相关块，不启动第二遍全稿生成或润色。教学数字不冒充实验；限制在相关位置说明一次即可。

### 写作形式

模型在首次生成时面向具备基本学科背景、尚未读过本论文的读者，用平实、清楚的中文讲解：

- 句子交代清楚“谁／什么对象做什么、怎样变化”。新段落、话题转折或执行者切换时明确主语，可用算法、变量、实验或作者作主语；同一主语连续叙述时自然省略，不逐句机械补“我／AI”。多个对象同时出现时，用具体名称消除“它、其、这”的歧义。
- 段首交代本段要点，一段集中推进一个意思。方法段连接对象、动作、变化与下一步；结果段连接实验条件、指标、证据与判断；推导段交代前提和中间关系。模型按内容选择自然结构，不把每段套成相同模板。
- 正文用完整句和连续自然段推进解释，长句在逻辑转折处拆开。列表承载真实步骤或并列项目，表格承载比较，不把连续推理拆成碎标题、操作口令或零散短条。术语就地解释，必要例子帮助读者跟上思路。
- 正文先交代图或公式要解决的问题，再解释关键变化、符号及结论怎样支持当前论点。指代清楚的文字承担解释，图表与公式作为配合，不能只写“见图／由公式可知”。
- 主张强度随证据而定：适用条件写具体，真实不确定性说明来源，必要边界就近说明一次。模型保留实际权衡、不利结果和关键限定，删除空泛评价、重复免责与自我限定，不机械禁词，也不因文风改动原式、数字或引文。

这些形式用于AI概览、详解与讲解，全文译文按忠实翻译规则处理。模型直接在本次创作中应用，不增加语言编辑agent、第二遍全文润色或文风评分；确需更多例子时再查[完整写作形式与示例](plain_language_zh.md)。

### 读取与续写

已读且未改的正文、技能和图像不再次全量加载。先读本短指南和原文，再一次组织最终数据；查字段用关键词定位少量行，不通读脚本或全部参考资料。写入成功后用 `inspect_reading_content.py` 取计数，不能 `cat` 整份成品来确认。相互独立的读取/检查合批，依赖操作顺序执行；失败只返回错误及邻近片段，禁止截断后再重读全文。

文件路径只是本地引用，不是模型已读内容：首次仍须读所需原文；后续沿用该环节当前会话，不把相同大段材料当新消息再次附上。按用户选择分配模型，保持同一环节的模型、推理档位、工具定义和稳定指令不变，变化内容追加在后续消息，不修改已经发送的旧消息。交接只给必要原文/图页路径和目标，不继承或粘贴整段父会话，不传其他环节成品全文；能使用同一模型的同一创作上下文时不额外拆分。不为缓存而保留无用大上下文，也不反复创建新会话重灌全文。缓存由宿主处理，首次读取、换模型、路由或失效可能造成未命中；不得宣称仅靠 skill 能保证命中。统计分别记录输入、缓存输入和输出。

## 原图与必要可视化

写到图表所支持的内容时，就在相邻段落边界插入；避免把整章图片堆到章末。裁图保留图号、轴、图例和比较条件，清除无关残片。多方案或前后对比尽量在同一视野呈现，兼顾图中文字可读性，避免不必要的纵向长图。图注简短指明看什么，推理写在正文。

方法总图默认按[draw-science 阅读器精简入口](visual_authoring_guide.md)制作中文静态图，采用科学对象示意、局部变化与功能分区；按真实拓扑排版，主链、并行、汇合、反馈与输出一次可见。输出本地 SVG（优先）或高清 PNG，以普通 `figure` 嵌入，可编辑源/配置作为 `assets/` 中的最终图资产保留。按实际面板宽度控制字号和箭头，不能把1600宽画布直接缩到640后仍当作可读。制作后只看局部摘要和一次目标尺寸渲染，纳入已有两张截图额度，正常即结束。原始实验图、照片与数值曲线保留原始信息；原文补充表格直接整理成最终可读表格。

其他可视化优先复用原图或静态示意；需要观察对象追踪或参数变化时再用现有交互组件。组件不适合时用准确的静态图，不开发新组件。需要字段时只查[组件合同](learning_support_guide.md)对应类型；确需新绘局部图再查[制图适配](visual_authoring_guide.md)。

## 填入阅读器

在 skill 目录运行；已有 `paper-data.js` 时直接更新，保留稳定 ID：

```sh
python scripts/init_reading_content.py --paper-id <id> --preset method --output <论文目录>/paper-data.js
```

`--preset` 也可选 `theory`、`survey`、`system`。脚手架默认带五节概览、详解和静态方法总图位置，不创建待办文件。把详解的示例章替换为实际论文大章节；直接填入正文、图、表和公式。方法图资源默认写入 `assets/method-framework.svg`，不另造交互数据。

- 文件仅为 `window.PAPER_DATA = <标准JSON>;`，保持 `schema_version:3`、`content_contract_version:"3.2"`。
- `overview.sections` 和 `explanation.sections` 分别填概览与详解；每节有稳定 `id`、`title_cn` 和 `blocks`。普通段落用 `{id,type:"paragraph",text_zh,evidence_kind:"ai_explanation"}`，转述原文用 `paper`，自拟例子用 `teaching_example`。
- 方法总图填在已登记的 `overview-method-framework` figure 块中，保留 `learning_requirements.overview_framework:{kind:"static_figure",section_id:"overview-method",block_id:"overview-method-framework"}`。脚本检查引用及本地资源；旧交互稿兼容，但新稿不传 `--with-method-pipeline`。
- 独立公式用 `type:"formula"` 和裸 `latex`，段落内用 `\(...\)`；JSON 反斜杠双写。图用 `type:"figure"` 和论文目录内相对 `src`，表用 `type:"table"` 的 `headers/rows`，算法可用 `algorithm/code`。具体字段不清时只查[数据格式](paper_data_schema.md)相关部分。
- 新稿保留 `translation:{status:"deferred"}` 和顶层 `sections:[]`；用户触发后才填全文译文。
- 图文内容填完后设 `content_status:"ready"`；`content_review` 可省略，不填写虚构审核记录。

## 交付

```sh
python scripts/deploy_reader.py --vault <库> --paper <id>
python scripts/open_reader.py --vault <库> <id>
```

需要计数时运行 `python scripts/inspect_reading_content.py <论文目录>/paper-data.js`；只需要某处原文时加 `--block-id <id>` 或 `--section-id <id>`，输出有界，不读回全篇。新论文需要入库时在生成脚本中调用 `vault_manager.upsert_paper(vault, {"id":id,"title":title_en,"title_cn":title_cn,"authors":authors,"year":year,"venue":venue})`，已有条目按现状保留，无须搜索多个管理脚本。未要求接通答疑时，打开命令加 `--bridge none`；由宿主工具展示页面时再加 `--no-open`。

部署已检查 JSON、ID、资源和方法图引用，复用其结果。常规显示确认只有一轮：方法图一张截图、详解中一个代表性图文区域一张截图，以及一次图片加载/公式错误计数；已有其中一项结果则直接复用。两张截图与计数正常即交付，禁止继续逐章翻页、滚动巡检其他同类图片、重复找目录或再做一轮相同计数。只在发现具体错误时修该处并局部复查；改裁图只更新该资源，不重新生成未变正文或重复部署整库。图片看过且可读，不再为数量统计截图。

按浏览器工具规定取得必要初始状态；将定位、点击、操作后状态筛选和截图合批，状态只返回导航控件、目标块或错误计数。禁止输出 `document.body.innerText`、整篇详解 DOM/可访问性树、`getAXState({disableDiffing:true})` 全文。若 API 只能生成全树，使用不输出模式在工具内筛选后返回，不能输出原始树。实际渲染全文不等于回传全文。公式检查仅返回错误计数、出错块 ID 与短信息；无错误则不再读取公式或源码。正常交付不生成验收报告、不开展全文重审、多端回归或真实答疑调用。

续写和局部修订沿用已有上下文，只补受影响内容；用户专门要求审阅或调试时再执行对应工作。
