# 8 类 AI 精读伴读批注规范指南 (Annotation Guide)

## 1. 批注原则与密度

- **核心目的**：降低认知门槛，穿透深层数学与工程细节，启发批判性思考；
- **密度控制（用户定调：越多越好）**：**每个 block 至少 1 条批注**，核心块（公式 / 主实验表 / 关键方法设计 / 核心结论段）2~3 条；参考基准：34 块的论文约 44 条。批注是本工作流的核心价值之一，宁可多写再删，不可留空块；挡位只影响**解释深度**（新手档重释义+比喻 / 熟练档轻解释），不影响条数。
- **严禁无意义水批注**：禁止出现“这个方法很好”、“此处很关键”等无信息增量的废话。

---

## 2. 8 类批注分类与触发时机

| 分类 | 标识/CSS类 | 触发位置 | 批注内容规范 |
| :--- | :--- | :--- | :--- |
| **1. 概念解释** | `concept` | 出现复杂学术概念、冷门数学术语处，以及**任何术语首次出现且译文中未解释时** | 用**生活化通俗类比**拆解复杂概念的物理本质与几何意义。首现术语必须被解释：新手档重释义+比喻，熟练档一句轻解释（也可内嵌在 text_zh 括注里，二选一不重复）。 |
| **2. 关键结论** | `key-conclusion` | 摘要、引言末尾、结论章节 | 提炼本文最核心的技术突破与学术贡献，一针见血指出创新点。 |
| **3. 方法理解** | `method` | 方法论章节、算法流程处 | 拆解数据流走向、为什么这样设计模块、前后处理的衔接逻辑。 |
| **4. 公式解读** | `formula` | 核心数学公式、目标损失函数处 | 逐个拆解公式中每一个符号的物理含义、约束作用与梯度传导意义。 |
| **5. 图表解读** | `figure` | 框架图、流程图、对比示意图处 | 详细指引读图顺序（先看哪、再看哪），解读箭头与特征流动。 |
| **6. 实验分析** | `experiment` | 主实验表格、对比柱状图处 | 指出最关键的基准提升、SOTA 指标对比与核心结论支撑点。 |
| **7. 阅读提醒** | `reading-reminder` | 容易引起误解、需前后对照的细节 | 提醒读者注意作者使用的特殊定义、边界约束或超参数设定。 |
| **8. 批判性思考** | `critical-thinking` | 讨论、消融实验、局限性章节 | 从审稿人视角指出作者未明说的理想假设、失效场景与潜在漏洞。 |

## 3. 批注在 paper-data.js 中的落地形式

批注**不写 HTML**，作为 block 的 `annotations` 数组字段，由阅读器统一渲染成卡片：

```json
{
  "id": "b-3-4",
  "type": "formula",
  "latex": "W_{v,j}=\\text{Softmax}_j(\\langle \\psi_v(x_v), \\phi_j(k_j) \\rangle / \\tau)",
  "text_zh": "……逐符号解读……",
  "annotations": [
    {
      "type": "formula",
      "title": "Dual Skin 内积软分配",
      "body": "<b>物理意义</b>：网络输出固定维度的特征场，蒙皮权重由顶点特征与关节特征的内积相似度自适应得出，解决了变长关节的维度扩展难题。"
    }
  ]
}
```

- `type` 取上表"标识/CSS类"列的 8 个值之一（卡片配色与图标由阅读器按此渲染）；
- `body` 内可用行内 `$...$` 数学与 `<b>` `<i>` `<br>`；
- 密度基准：**每个 block ≥1 条**、核心块 2~3 条；类型分布要多样——method / critical-thinking / concept 为主力，主实验表必有 experiment、关键框架图必有 figure、易读丢的段落给 reading-reminder 导航；每条必须提供"只读正文读不出来"的增量（读表方法、设计动机、审稿人视角、复现警告）。
